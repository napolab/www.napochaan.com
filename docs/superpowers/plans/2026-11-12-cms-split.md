# CMS 分離（cms.napochaan.com + 表示専用 www）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Payload CMS を `apps/cms`（cms.napochaan.com、Access 内）に分離し、`apps/web`（napochaan.com）を Payload 非依存・SSR + Workers Cache の表示専用 Worker にする。

**Architecture:** pnpm monorepo。web → cms は Hono RPC: shared パッケージ `@napochaan/cms-api` の `createApp(services)` を cms が Payload 実装で組み立てて named entrypoint `CMS` の `fetch` で公開し、web は `hc<CMSAppType>` に `env.CMS.fetch` を渡して呼ぶ。画像の元データも同じ経路のストリーム応答で受け取り、web が `/api/media/file/*` と `/_next/image` で配信する。cms → web は `WEB` binding の `purge()` RPC で Workers Cache を全消しする。

**Tech Stack:** pnpm workspaces, Next.js + @opennextjs/cloudflare（両 app）, Payload 3.91, Cloudflare Workers（Service Binding RPC / Workers Cache / Images / D1 / R2 / Access）, vitest（browser mode + workers pool）, oxlint/oxfmt, tsgo。

**Spec:** `docs/superpowers/specs/2026-11-12-cms-split-design.md`（根拠: `reports/2026-11-12-cms-split-research.md`）

## Global Constraints

- 勝手に commit しない。各タスクの最後は `pnpm lint && pnpm typecheck && pnpm test` → **difit を起動してユーザーにレビュー依頼** → 承認後に commit（以下の Commit ステップはすべてこの意味）。
- ブランチは `git fetch origin main` 後に `origin/main` から切る（`.claude/rules/git-workflow.md`）。
- Worker 名: web = 既存 `napochaan-website` / `napochaan-website-staging` / `napochaan-website-production`（維持）。cms = `napochaan-cms` / `napochaan-cms-staging` / `napochaan-cms-production`。
- ホスト: web `napochaan.com` / `stg.napochaan.com`、cms `cms.napochaan.com` / `cms-stg.napochaan.com`。
- D1 / R2 は既存（`napochaan-cms-{dev,staging,production}`）を cms に付け替えるだけ。新規作成・データ移行しない。
- web → cms は RPC のみ。web から cms を HTTP fetch しない。
- web → cms は `hc<CMSAppType>` 経由のみ（Service Binding の `fetch`）。cms → web の purge だけは JS RPC（web default entrypoint の `purge()`）。
- `@napochaan/cms-api` は型・zod・ルート定義のみ（Payload / Cloudflare 実装を import しない）。応答は DTO のみで、Lexical state は `JSON.stringify` した string。
- web に残してよい Payload 系 value import は `@payloadcms/richtext-lexical/react` と `@payloadcms/live-preview-react` のみ（型 import は可）。
- 画像の公開 URL は `/api/media/file/<filename>`（相対）のまま変えない。
- 本番 web は Access 保護パスなし。stg web はホスト全体 Access を維持。cms はホスト全体 Access（Managed OAuth ON）、`/api/media-upload` のみ Bypass。
- purge は全消し（`purgeEverything: true`）。spike で不成立なら CMS 由来ページは `max-age=60, stale-while-revalidate` にフォールバック（ユーザー決定: 1 分程度の遅延は可）。
- `Cache-Control` に `s-maxage` / `must-revalidate` を使わない。
- `tsconfig.json` の `paths` は変更前にユーザーに確認する（`.claude/rules/coding-rules.md`）。monorepo 化で各 app の tsconfig に同じ alias を置くのは「移動」として Task 1 で確認を取る。
- `CLAUDE.md` の変更はユーザー確認後。
- コーディング規約は `.claude/rules/*.md`（arrow function、`let` 禁止、`satisfies`、early return、no barrel、acronym casing: `CMS` / `RPC` / `URL` / `ID`）。

## Review Focus

1. **rich text 内の画像**: blog/news/profile 本文の upload / image-row ノードが RPC 経由でも populate 済み（`url,width,height,alt,mimeType,filename`）で届くこと → Task 4 に projection テスト追加。
2. **存在しない画像 / slug**: `mediaFile('nope.png')` → web は 404（500 ではない）、`blogBySlug('nope')` → `notFound()` → Task 5 / Task 8 にテスト。
3. **プレビュー secret 不一致**: 誤った `previewSecret` で下書き RPC を呼ぶと `{ status: 'forbidden' }`、web の `/next/preview` は 403 → Task 5 / Task 9。
4. **ファイル名のパス操作**: `mediaFile('../x')` や `%2F` を含む名前は R2 キーとして解決しない（null）→ Task 5。
5. **CLI（seed / migrate）からの書込み**: Payload フックが `env.WEB` も request context もない状態で呼ばれても例外を出さない → Task 7。
